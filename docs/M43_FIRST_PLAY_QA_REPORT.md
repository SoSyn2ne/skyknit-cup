# M43 첫 3분 플레이 QA 기록

> 상태: 자동·실브라우저 검증 완료 / 사람·실기기 플레이테스트 미실시 — 2026-08-28

## 구현 결과

- 시작 안내를 구체화했다. 키보드는 `Enter 시작 · 방향키/WASD 비행 · Space/Shift 돌풍`, 터치는 `왼쪽 스틱으로 비행 · 오른쪽 버튼으로 돌풍`을 표시한다.
- 기존 미션 트래커의 두 번째 줄을 잠깐 바꿔 `코스 이탈 · 관문 복귀 준비`, `충돌 감속 · 곧 회복`, `관문 복귀 · 기록 계속`을 안내한다. 별도 패널이나 영구적인 세 번째 줄은 추가하지 않았다.
- 화면 안의 관문도 HUD에 가리면 기존 금색 방향표를 표시한다. 방향표는 같은 방향을 유지하면서 HUD·터치 버튼을 피하는 위치로 이동한다.
- HUD 경계는 화면 크기·레이스 단계·미션·공지·조작 UI 상태가 바뀔 때만 다시 측정한다. 동전 방향표는 기존 호출 경로를 유지한다.

## 실제 입력의 수정 전후 비교

기준 커밋은 `016b400`이다. 아래 값은 **읽기 전용 스냅샷을 이용한 자동 키보드/CDP 터치 조작**의 측정값이다. 사람의 첫 플레이 또는 실제 휴대기기 결과가 아니다.

| 화면 | 입력 | 수정 전 레이스 시간 | 수정 후 레이스 시간 | 수정 후 벽시계 시간 | 결과 |
| --- | --- | ---: | ---: | ---: | --- |
| 1440×900 | 키보드 | 83.283s | 82.983s | 87.309s | 0→8 / 재도전 성공 |
| 1280×720 | 키보드 | 82.900s | 82.867s | 87.121s | 0→8 / 재도전 성공 |
| 844×390 | 터치 | 82.733s | 82.783s | 86.765s | 0→8 / 재도전 성공 |
| 390×844 | 터치 | 82.733s | 82.750s | 86.788s | 0→8 / 재도전 성공 |
| 320×568 | 터치 | 82.717s | 82.733s | 86.755s | 0→8 / 재도전 성공 |

- 모든 완주 실행에서 진행은 정확히 0→1→2→3→4→5→6→7→8이었다. 키보드는 결과 버튼의 포커스에서 Enter 한 번, 터치는 버튼 탭 한 번으로 재도전해 다시 racing에 진입했다.
- 작은 시간 차이는 자동 입력/호스트 실행 타이밍의 차이이며 물리나 코스를 빠르게 조정한 결과가 아니다. 벽시계 시간에는 로딩·카운트다운·QA 화면 저장이 포함된다.
- 테스트 코드에서 관문 통과·위치·레이스 단계를 직접 바꾸거나 가짜 시간을 쓰지 않는다. 기존 QA 지름길 테스트는 빠른 상태 계약용으로 남기되, 이 완주의 증거로 사용하지 않는다.
- 수정 전: `artifacts/browser-qa/m43-baseline/`
- 최종: `artifacts/browser-qa/m43-navigation-final/`
- 각 폴더의 `*-m43-telemetry.json`, 관문별 PNG, 결과/재도전 PNG와 WebM으로 재현 경로를 확인할 수 있다.

## 복귀·충돌 검증

5개 화면 모두 별도 실제 입력 프로브로 확인했다.

- **자동 복귀:** 실제 첫 관문을 먼저 통과한 뒤 비행로를 이탈했다. 복귀 전후 race/mission 진행은 모두 1→1로 유지됐고, 타이머는 계속 증가했다. 이탈 안내와 복귀 안내를 실제 HUD에서 확인했다.
- **충돌 회복:** 첫 관문 이후 기존 `festival-spire (50, 4, -330)`로 비행해 실제 충돌을 유도했다. 충돌 횟수 증가, 감속 안내, 회복 시간 종료·속도 배율 1, 정상 진행 문구 복귀를 확인했다. 리스폰 횟수와 race/mission 진행은 변하지 않았다.
- 충돌의 `lastObstacleId`는 이력 값이므로 회복 판정에 사용하지 않는다. 실제 회복 시간·속도·진행·리스폰 횟수를 검증한다.
- 이 프로브의 자동 복귀는 게임 기능을 정상 입력으로 유도한 것이며, 전체 코스 완주를 대신하는 순간이동/통과 훅이 아니다.
- `*-m43-recovery-telemetry.json`, `*-m43-collision-telemetry.json`과 전/중/후 PNG·WebM을 남겼다.
- 완주·복귀·충돌의 console/page/HTTP 오류는 모두 0이었다.

## 관문 가림 재현과 보완

강화된 검사에서 처음에는 15개 중 14개가 통과하고 가로 터치 비행 1개가 실패했다. progress 4 직후 다음 관문 중심 `(725.99, 70.65)`가 우상단 관문 카운터에 가렸다.

| 비교 | 사용된 안내 | HUD 가림 |
| --- | --- | --- |
| 수정 전 | 카운터 뒤의 관문 중심 | 있음 |
| 수정 후 | HUD 밖의 금색 방향표, 약 `(602.94, 32.00)` | 없음 |

- 해당 전후 PNG와 측정값은 `artifacts/browser-qa/m43-occlusion-before/`, `m43-occlusion-after/`에 별도로 보존했다.
- 테스트는 클릭 가능 여부가 아닌 표시 영역의 실제 사각형으로 가림을 판단한다. 따라서 `pointer-events:none`인 HUD도 빠뜨리지 않는다.
- 완주 직후에는 목표가 없으므로 가독성 검사에서 제외한다. 비행 중에는 48px 이상 관문 또는 화면 안의 방향표 중 하나가 보여야 하고, 해당 안내가 HUD/조작 영역에 가리지 않아야 한다.
- 최종 5개 화면에서 검사한 모든 관문 전환의 안내 가림은 0건이었다. 화면 밖 관문 자체를 결함으로 취급하지 않고, 실제 금색 방향표가 읽히는지 확인했다.
- 캔버스는 5개 화면 모두 밝기 범위 40 초과 및 시간에 따른 픽셀 해시 변화를 확인했다. 최종 시각 판정은 `.omx/state/m43-first-play/ralph-progress.json`에 기록했다.

## 남은 위험과 사람·실기기 확인

- 사람이 실제로 처음 조작을 이해하는 속도·재미·체감 난이도 및 실물 휴대기기 GPU 성능은 미검증이다. 자동 입력 결과로 대체하거나 완료한 것으로 기록하지 않는다.
- HUD 크기를 바꾸는 새 동적 규칙을 추가할 때에는 경계 캐시의 무효화 조건과 가림 회귀 검사를 함께 갱신해야 한다.
