# Milestone 33 Sky League 플레이테스트 인계

> 자동 상태: **전체 자동 검증 완료**
>
> 사람 상태: **새 저장·v7 저장 10~15분 실기기 플레이테스트 대기**
>
> 출시 상태: **완료 아님**

## 테스트 목표

Sky League가 단순한 기록 목록이 아니라 “한 번 더 날고 싶은” 오프라인 경쟁 루프인지 확인한다. 첫 완주가 Top 10과 1위 고스트를 만들고, 다음 시도에서 상세 드래곤의 비행선과 signed delta가 실제 조작 판단에 도움이 되어야 한다. 동시에 M32 오픈월드, 여섯 미션, 하늘동전, `Sovereign of the Sunrise Skies`, 저장과 복구가 그대로 유지되어야 한다.

자동화는 규칙과 결정적 상태를 확인한다. 사람은 고스트가 방해물이 아닌 라이벌로 읽히는지, delta를 비행 중 이해할 수 있는지, 결과 화면이 재도전을 자연스럽게 유도하는지, 실제 기기에서 지역 전환·오디오·발열이 안정적인지를 판정한다.

## 실행 준비

- Node.js `22.20.x`
- 브랜치 `codex/m33-sky-league`
- 새 저장용 브라우저 프로필 1개
- M32 v7 저장을 유지한 브라우저 프로필 1개
- 실제 Android Chromium과 iPhone Safari
- 콘솔·네트워크 로그, 스크린샷과 10초 이상 영상을 남길 수 있는 환경

```powershell
npm run build
npm run preview -- --host 0.0.0.0 --port 4173
```

데스크톱은 `http://127.0.0.1:4173/`, 모바일은 preview 터미널에 표시된 PC의 LAN 주소로 접속한다. 새 저장과 v7 저장은 같은 브라우저 프로필에서 섞지 않는다. v7 프로필은 시작 전에 사이트 저장소의 `skyknit-cup:settings` 값을 별도 파일에 백업한다.

## 세션 A: 새 저장 10~15분

사이트 저장소가 비어 있는 새 프로필에서 진행한다. 자동 QA 이동을 사용하지 않는다.

### 0~3분: 첫 레이스·미션 기록

1. `첫 하늘매듭`을 선택하고 비행을 시작한다.
2. 12개 관문을 순서대로 완주한다.
3. 결과 첫 화면에서 이번 기록, 최고 기록 대비, 전체 레이스 `1위 · 금메달`, 미션 `1위 · 금메달`을 확인한다.
4. `로컬 Top 10 보기`를 열어 전체 레이스와 선택 미션을 전환한다. 각 기록판에 한 행만 있고 현재 선택 버튼의 상태가 분명해야 한다.
5. 기록판을 펼친 상태에서도 `다시 달리기`가 viewport 안에 보여야 한다.

### 3~6분: 1위 고스트와 실시간 차이

1. `다시 달리기`를 누른다.
2. 청록·금색 반투명 고스트가 출발하고 머리, 날개와 꼬리를 읽을 수 있는지 본다.
3. 관문 2~3개 동안 고스트보다 안쪽·바깥쪽 비행선을 번갈아 탄다.
4. 같은 진행 구간에서 음수 delta는 빠름, 양수 delta는 느림으로 자연스럽게 이해되는지 확인한다.
5. 고스트가 관문, 플레이어 드래곤과 다음 진행 방향을 가리지 않고 충돌·카메라·오디오에 영향을 주지 않아야 한다.
6. 일부러 첫 기록보다 느리게 완주한다. 새 기록은 2위로 들어가되 세 번째 시도의 고스트는 첫 1위 비행선을 유지해야 한다.

### 6~10분: 지역 하늘동전 기록

1. `하늘 탐험`으로 들어가 축제 중심섬 동전 10개를 순서대로 수집한다.
2. 완료 뒤 지역 `1위 · 금메달`과 Top 10 한 행을 확인한다.
3. 같은 지역 동전을 다시 시작한다. 현재 지역 1위 고스트와 동전 delta가 보여야 한다.
4. 두 번째 시도를 일부러 느리게 완료하고 `2위`가 추가되는지 본다.
5. 지도 안에서 현재 지역 Top 10을 열고 닫을 수 있어야 하며, 지도 중 비행과 기록 시간은 멈춰야 한다.

### 10~15분: reload·복구·오디오

1. 새로고침하고 race, mission, coin Top 10과 1위 고스트가 유지되는지 확인한다.
2. 새로고침 직후 사용자 동작 전에는 BGM이 자동재생되지 않아야 한다.
3. 다시 비행을 시작하면 `Sovereign of the Sunrise Skies`가 한 번만 이어지고 날갯짓과 돌풍 `슈우웅`이 중복되지 않아야 한다.
4. 가능하면 레이스 중간에 WebGL context loss를 유도하고 `다시 시도` 뒤 `계속 날기`를 누른다.
5. 관문 진행, recorder와 고정된 비교 고스트가 이어지고 완주 뒤 canonical 고스트를 저장할 수 있어야 한다.

## 세션 B: 기존 v7 저장 10~15분

M32에서 실제로 사용하던 v7 프로필로 진행한다. 시작 전에 레이스 최고, 지역 동전 최고, 미션 최고 등급, 발견 지역·랜드마크·상승기류, 착륙 위치, 목적지, mute, BGM 볼륨과 품질을 기록한다.

1. M33을 처음 연 뒤 기존 레이스 최고가 전체 레이스 Top 10 한 행으로 보이는지 확인한다.
2. 각 기존 지역 동전 최고가 해당 지역 Top 10 한 행으로 보이는지 확인한다.
3. 기존 미션 최고 등급은 유지되지만, v7에 완주 시간이 없으므로 미션 Top 10은 비어 있어야 한다.
4. M32 발견과 탐험 위치·착륙, 목적지, 음소거, BGM 볼륨과 품질이 그대로인지 확인한다.
5. 기존 최고가 있는 종목을 다시 시작한다. 아직 저장 고스트가 없으면 `기준 없음`이어야 하며 플레이는 정상 진행되어야 한다.
6. 기존 최고보다 빠른 레이스 또는 동전 기록을 하나 만들고 새 1위 고스트가 생기는지 확인한다.
7. 성공 미션 하나를 완주해 그 미션의 첫 Top 10 시간과 고스트를 만든다.
8. 새로고침 뒤 모든 Top 10, 고스트와 기존 M32 진행이 함께 유지되는지 확인한다.
9. 세션 종료 뒤 백업한 v7 원본과 현재 v8 값을 함께 보존한다.

## 기록판·메달 판정

- race와 coin은 시간이 빠른 순서로 정렬되어야 한다.
- mission은 `골드 > 실버 > 브론즈`, 같은 등급 안에서 빠른 순서여야 한다.
- 정확한 동률에서는 먼저 있던 기록이 앞에 남고 새 기록은 다음 번호를 받아야 한다.
- 1·2·3위는 금·은·동 텍스트와 색을 함께 보여야 한다. 색만으로 메달을 구분하면 실패다.
- 4~10위는 숫자만 보이고 11번째 이하 기록은 목록을 10개 이상 늘리면 안 된다.
- 실패 미션은 전체 레이스 기록에는 들어갈 수 있지만 해당 미션 Top 10에는 들어가면 안 된다.
- 결과 알림은 한 번만 읽히고 프레임마다 바뀌는 live delta는 `aria-live`로 반복 안내되면 안 된다.

## 1위 고스트 판정

1. 첫 1위 기록에서 눈에 띄는 선회 경로 하나를 만든다.
2. 두 번째 시도는 의도적으로 느리고 다른 경로로 완주한다.
3. 세 번째 시도에서 고스트가 첫 1위 경로와 시간을 재생하는지 비교한다.
4. race, 선택 mission과 현재 coin 지역을 각각 확인한다.
5. 선택 미션 고스트가 있으면 전체 레이스 고스트보다 우선해야 한다.
6. 다른 지역으로 이동하면 이전 지역 동전 고스트가 남아 있으면 안 된다.
7. pause, 지도, 탭 숨김 중에는 고스트와 delta가 멈추고 복귀 뒤 갑자기 건너뛰지 않아야 한다.
8. 고스트는 그림자를 만들거나 충돌시키고, 관문·동전·발견을 대신 통과하거나 카메라를 끌어당기면 안 된다.

## 지역 전환 급선회 확인

30초 자동 성능은 Sky League 자체 비용을 재현하기 위해 고스트가 활성화된 현재 코스의 steady-state를 측정했다. 인접 지역 LOD 겹침을 기능 비용으로 오인해 임계값을 낮추는 방식은 사용하지 않았다.

사람 테스트에서는 별도로 지역 경계를 왕복한다.

1. 축제 중심섬과 인접 지역 경계로 이동한다.
2. 경계를 따라 넓게 한 번 선회한 뒤, 짧은 반경으로 5회 이상 왕복 선회한다.
3. 각 방향에서 고스트가 보이는 기록 시도를 함께 진행한다.
4. 순간 멈춤, 지역 구조물 pop, 두 LOD 겹침, 고스트 가림과 카메라 흔들림을 기록한다.
5. 경계를 벗어나 steady-state로 돌아온 뒤 프레임이 회복되고 이전 지역 자원이 정리되는지 본다.
6. 같은 동작을 desktop high와 mobile low에서 반복한다.

이 구간의 순간 부하는 steady-state 성능표만으로 출시 판정하지 않는다. full-duration 10분 soak 결과와 실제 기기 영상이 모두 필요하다.

## 오디오 필수 순서

1. 첫 사용자 동작 전: BGM, 바람층과 효과음이 모두 조용해야 한다.
2. 첫 비행 시작: BGM이 한 번 시작하고 기존 재생 위치 정책을 유지해야 한다.
3. 고스트 추격: 고스트 자체에서는 날갯짓, 돌풍과 충돌음이 나면 안 된다.
4. 플레이어 날갯짓: 날개 하강 박자의 에어 펄스가 BGM과 delta 판단을 방해하지 않아야 한다.
5. 플레이어 돌풍: 0.78초 `슈우웅`이 귀여운 짧은 효과음으로 돌아가거나 BGM을 덮으면 안 된다.
6. race ↔ explore ↔ mission: BGM 위치가 이어지고 AudioContext가 중복 생성되지 않아야 한다.
7. mute와 BGM 0%·35%·100%: mute는 전체 오디오, BGM 슬라이더는 음악만 조절해야 한다.
8. 탭 숨김·복귀와 context recovery: 중복 재생, 위치 초기화와 갑작스러운 gain 증가가 없어야 한다.

## 사람 통과 기준

- 첫 완주 뒤 별도 설명 없이 순위, 메달과 Top 10을 이해하고 재시도를 선택한다.
- 두 번째 시도에서 상세 고스트를 라이벌로 읽고 signed delta의 빠름·느림을 올바르게 해석한다.
- 느린 2~10위 기록이 목록에는 들어가지만 1위 고스트를 교체하지 않는다.
- race, mission과 세 coin 지역 기록판이 서로 섞이지 않고 reload 뒤 유지된다.
- v7의 기존 기록, 미션 등급, M32 발견·위치, 오디오와 품질이 손실되지 않는다.
- context recovery 뒤 진행 중 recorder와 비교 고스트가 이어지고 중복 기록·오디오가 생기지 않는다.
- 다섯 기준 viewport에서 결과, retry와 44px 동작이 보이고 기록판만 내부 스크롤한다.
- 실제 Android와 iPhone에서 10~15분 동안 심한 발열, throttling, 터치 피로와 UI 겹침이 없다.
- 지역 경계 급선회 뒤 steady-state 성능과 자원이 회복된다.
- 자동 검증 증거와 사람 테스트 결과가 충돌하면 사람에게 재현된 문제를 우선해 수정한다.
