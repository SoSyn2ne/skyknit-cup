# RC5 3D 월드 아트 플레이테스트 인계

> 자동 상태: **RC5 / 3D 월드 아트 패스 자동 검증 완료**
>
> 사람 상태: **실기기·사람 플레이테스트 대기**

## 테스트 목표

Blender로 제작한 세 지역의 3D 구조물이 드래곤 비행 중 명확하게 읽히고, 거리 LOD 전환과 모바일 저품질 모델이 발견의 재미나 조작 가독성을 해치지 않는지 확인한다.

## 기술 기준

- 런타임은 기존 Vite + Three.js를 유지한다. Unity 이전은 필요하지 않다.
- 원본은 `assets/source/world/skyknit-world-rc5.blend`, 런타임은 지역별 high/low GLB 6개다.
- 데스크톱 high는 220 units 안에서 high로 올라가고 260 units 밖에서 low로 내려간다.
- 모바일과 low 설정은 항상 low GLB를 사용한다.
- 지역 자체는 기존처럼 420 units 안에서 로드되고 500 units 밖에서 언로드된다.

## 권장 기기

- 데스크톱 Chromium 키보드, 1440×900 이상
- 실제 Android 또는 iPhone 가로 화면
- 실제 Android 또는 iPhone 세로 화면
- 가능하면 4GB급 저사양 Android 한 대

## 확인 순서

1. `하늘 탐험`으로 들어가 축제 중심섬의 비행장, 축제 탑, 깃발, 레이스 아치를 한눈에 구분한다.
2. 바람 협곡으로 이동하며 먼 거리 low 모델에서 가까운 high 모델로 바뀔 때 심한 깜빡임이나 끊김이 없는지 본다.
3. 협곡의 양쪽 절벽, 풍화 터널, 바람 고리, 끊어진 다리가 하나의 비행 동선으로 읽히는지 확인한다.
4. 구름 유적에서 사원 지붕, 계단, 출입구, 룬 기둥, 부유 석판이 착륙장과 드래곤을 가리지 않는지 본다.
5. 각 지역에서 착륙·재이륙하고 구조물 가까이 선회해 카메라가 벽 안으로 과도하게 파고드는지 확인한다.
6. 지도와 목적지 안내를 켠 채 세 지역을 왕복해 LOD 전환, 지역 로드/언로드, 저장 복원이 자연스러운지 본다.
7. 축제 중심섬의 레이스 도전으로 들어가 6개 미션, 완주, 리스폰, 재시도가 RC4와 동일하게 동작하는지 본다.
8. 모바일에서 10분 이상 탐험해 발열, 배터리 소모, 프레임 저하, 엄지 조작 가림을 기록한다.

## 기록할 질문

- 세 지역이 색뿐 아니라 실루엣만으로도 구분되는가?
- 축제 탑과 사원 지붕이 화면 가장자리에서 너무 크게 잘리는가?
- 220/260 units LOD 전환이 눈에 띄거나 구조물 모양이 갑자기 바뀌는가?
- 바람 협곡의 터널과 구름 사원의 계단이 자연스럽게 다음 이동 방향을 알려 주는가?
- low 모델도 구조물 종류와 착륙 위치를 즉시 알아볼 수 있는가?
- 구조물 가까이 날 때 멀미, 카메라 클리핑, 조작 불능 구간이 있는가?
- 5~10분 뒤 실제 모바일에서 프레임이나 터치 반응이 나빠지는가?

## 문제 기록 형식

- 기기/OS/브라우저
- 화면 방향과 품질 설정
- 지역과 구조물 이름
- 대략적인 거리 또는 LOD 전환 전후
- 재현 순서
- 가능하면 10초 영상과 프레임 저하 시점

## 자동화로 대체할 수 없는 위험

- 실제 모바일 GPU 발열과 제조사별 throttling
- 고DPR 화면의 저폴리 가장자리 인상
- LOD 전환을 사람이 느끼는 정도
- 구조물 밀도와 발견 보상감
- 장시간 비행의 멀미, 피로, 카메라 클리핑

커밋, push, deploy는 수행하지 않았다.
