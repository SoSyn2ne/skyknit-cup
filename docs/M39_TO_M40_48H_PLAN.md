## 블록별 계획

### 블록 A — PR #1 머지 · D0, 30분

main을 RC6에서 M39까지 한 번에 따라잡는다. 이후 모든 블록의 기준선.

- PR #1을 머지한다(충돌 없음 확인됨). 머지 커밋 방식은 기존 관례(단일 브랜치 히스토리 유지)를 따른다.
- 머지 뒤 `codex/m39-volcanic-archipelago` 로컬·원격 브랜치는 유지한다(문서가 브랜치를 참조함).

**완료 조건**: `main` HEAD가 `20735af`(M39 인계 커밋)를 포함하고, 열린 PR이 0개다.

### 블록 B — CI 워크플로 · D0, 1~2시간

로컬에서만 돌던 검증 중 빠르고 결정적인 계층을 GitHub Actions로 올린다.

- `.github/workflows/ci.yml`: `main` push와 모든 PR에서 `npm ci` → `lint` → `typecheck` → `vitest run`.
- Node는 `package.json` engines(`>=22.20 <23`)에 맞춰 22.x로 고정한다.
- E2E·성능·production·asset audit는 CI에 올리지 않는다. 브라우저·GPU 의존 게이트를 처음부터 올리면 flaky 실패가 신뢰를 깎는다 — 기존대로 로컬 게이트로 유지하고, 필요해지면 별도 마일스톤에서 검토한다.

**완료 조건**: main에서 CI가 녹색이고, 이후 PR에 자동 검증 기록이 남는다.

### 블록 C — GitHub Pages 배포 · D0~D1, 2~3시간

사람 플레이테스트 빚을 풀기 위한 실제 URL을 만든다. 이 블록이 D·E·F의 선행 조건이다.

- `.github/workflows/deploy.yml`: `main` push 시 `vite build --base=/skyknit-cup/` → Pages artifact 업로드 → 배포.
- 저장소 Settings → Pages → Source를 **GitHub Actions**로 설정한다(`gh api`로 자동화 시도, 실패 시 웹에서 1회 수동 설정).
- 배포 전 `vite preview --base=/skyknit-cup/`로 하위 경로에서 에셋·GLB·오디오 로드가 깨지지 않는지 로컬에서 먼저 확인한다.
- 배포 후 첫 로딩 시간(에셋 21MB)을 PC·모바일 네트워크에서 실측해 기록한다.

**완료 조건**: `https://sosyn2ne.github.io/skyknit-cup/`에서 게임이 콘솔 오류 없이 로드되고, 레이스 시작까지 도달한다.

### 블록 D — 실기기 플레이테스트 · D1, 기기당 15~25분 × 3종

[M39_VOLCANIC_ARCHIPELAGO_PLAYTEST_HANDOFF.md](M39_VOLCANIC_ARCHIPELAGO_PLAYTEST_HANDOFF.md)의 15분 동선과 질문지를 그대로 사용한다.

- 기기: PC(마우스+키보드) / Android(320px급 세로 포함) / iPhone 또는 iPad Safari(소리 unlock 포함).
- 최우선 미검증 항목: **10분 이상 비행 시 발열·프레임 저하**(M39의 유일한 자동화 불가 게이트).
- 체감 질문: 용암 위험 예고(낙석 1.5초·파도 2초)가 공정하게 느껴지는지, 골드(45초·무충돌) 조건이 재도전 의욕을 만드는지, BGM·용암 앰비언스 균형, 세 수호수 선호.
- 결과는 `docs/M39_PLAYTEST_RESULT.md`에 인계 문서의 "실패로 기록할 조건" 기준으로 기록한다(기기/방향/수호수/재현 순서/스크린샷 포함).

**완료 조건**: 기기 3종 결과가 문서로 남고, 각 항목이 통과/실패/체감의견으로 분류된다.

### 블록 E — 발견 사항 분류와 수정 · D1~D2, 발견량에 비례

- 인계 문서의 "실패로 기록할 조건"에 해당하는 항목 → 즉시 핫픽스 브랜치로 수정하고 CI 통과 후 머지·재배포한다.
- 체감·선호 의견(예고 타이밍, 난이도, 오디오 밸런스) → 수정하지 않고 M40 입력으로 넘긴다.
- 발견이 없으면 이 블록은 건너뛴다.

**완료 조건**: 실패 조건 항목이 0건이거나, 각각 수정 커밋 또는 M40 이관 사유가 문서에 남는다.

### 블록 F — M40 범위 결정 · D2, 1시간

플레이테스트 결과를 근거로 다음 마일스톤을 승인한다. 배포·검증 루프 후보는 블록 B·C에서 해소되므로 후보는 세 갈래다.

| 후보 | 선택 근거가 되는 신호 |
| --- | --- |
| 화산 후속 폴리시(분화 변형, 화산재 실루엣·전경 톤) | 플레이테스트에서 용암 지역 인상·공정성 의견이 갈릴 때 |
| 캐릭터 확장(네 번째 종족, 세부 파츠, 이름 짓기) | 수호수 선호 답변이 뚜렷하고 지역 쪽 불만이 없을 때 |
| 다섯 번째 지역 / 새 챕터 | 위 둘 다 조용하고 "더 탐험할 곳" 요구가 나올 때 |

- 결정 후 `PRODUCT_GOAL.md`·`IMPLEMENTATION_PLAN.md`에 M40 범위를 고정 기록한다(다섯 번째 지역·네 번째 수호수는 별도 승인 없이 추가하지 않는다는 기존 원칙 유지).

**완료 조건**: M40 범위가 계획 문서에 승인 상태로 기록된다.
