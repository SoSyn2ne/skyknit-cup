## 테스트 우선 증거

M3 규칙은 구현 전에 실패 테스트로 고정했다.

1. `obstacleCollision.test.ts`는 충돌 모듈 부재 상태에서 RED를 확인한 뒤 선분-구 최초 교차, 0.45 감속, 1.25초 회복, 0.75초 cooldown, 리스폰 면역을 구현했다.
2. `flightModel.test.ts`는 외부 속도 배율 계약을 먼저 실패시킨 뒤 기존 비행 모델의 최종 속도 경계에 최소 연결했다.
3. `dragonPose.test.ts`는 어깨/몸통/꼬리 지연과 부스트/충돌 자세를 실패시킨 뒤 순수 포즈 상태로 구현했다.
4. `worldLayout.test.ts`는 군도 수, 고유 ID, 관문/중심선 여유, 충돌 가능한 측면 장애물을 실패시킨 뒤 데이터 배치를 구현했다.
5. `gateIndicator.test.ts`는 48 CSS px 경계, 화면 밖 방향, 32px 여백, 비정상 입력을 실패시킨 뒤 순수 투영 UI 규칙을 구현했다.
6. `cameraFeedback.test.ts`는 감소 모션에서 흔들림 0을 먼저 고정한 뒤 결정적 충돌 카메라 오프셋을 구현했다.

최종 결과는 16개 테스트 파일, 126개 테스트 통과다.

- 런타임: `public/assets/models/skyknit-dragon.glb`
- GLB 크기: 195,756 bytes
- Blender 검사: 94 mesh parts, 1,600 triangles
- 브라우저 런타임: GLB source, 93 meshes, 꼬리 피벗 5개

GLB와 Blender 원본은 모두 이 프로젝트에서 제작했으며 런타임 모델 README에 출처와 프로젝트 라이선스 범위를 기록했다. 현재 모델은 시각 정체성과 동작 검증을 위한 저폴리 블록아웃이므로 계획의 15,000~25,000 triangle 최종 모델 예산보다 의도적으로 작다.

## 실제 브라우저 기능 검증

Codex 인앱 브라우저에서 실제 키 입력과 개발 전용 QA 버튼으로 확인했다.

- 첫 화면에 주홍 드래곤, 좌우 바람실 2개, 금빛 관문, 청록 룬이 동시에 보였다.
- GLB 드래곤은 fallback 없이 로드됐고 5개 꼬리 피벗과 런타임 날개/몸통 포즈가 동작했다.
- 부스트 중 FOV는 약 62.6도까지 추종하고 공기고리 3개가 짧고 옅은 후류로 나타났다.
- 관문 통과 파동은 금빛 관문 바깥으로 청록 고리가 확장된 뒤 0.65초 안에 사라졌다.
- 충돌 후 속도 배율은 0.45에서 시작해 1.25초 동안 회복했고, 브라우저 캡처 중 0.626까지 회복하는 상태와 cooldown을 확인했다.
- 충돌 전후 레이스 phase와 다음 관문 인덱스는 유지됐으며 타이머/체크포인트를 직접 변경하는 경로가 없다.
- 감소 모션 강제 경로에서 부스트 중 FOV 55도, 공기고리 비표시, 충돌 카메라 흔들림 0을 확인했다. 산호색과 움찔 자세는 유지됐다.
- 실제 관문 투영 지름은 시작 화면에서 약 171 CSS px였다. 개발 전용 20px 강제 경로에서 방향 표시가 나타나고 각 뷰포트의 32px 가장자리 여백을 지켰다.
- 깨끗한 새 개발 세션과 프로덕션 미리보기의 console error는 0개였다.

`qaCollision`, `qaBoost`, `qaWave`, `qaGateIndicator`, `qaReducedMotion`, 기존 `qaCourse`, 강제 오류/테스트 훅은 프로덕션 JavaScript에 남지 않았다. 모든 QA 쿼리를 프로덕션 미리보기에 전달해도 정상 준비 화면만 표시되고 디버그 미러는 없었다.

## 성능과 전송량

- `1440x900` 10초 표본의 1초 버킷: 중앙값 55.4fps, 평균 56.8fps, 하한 54.4fps
- 같은 장면의 전체 10초 누적: 567 host frames, 600 fixed steps, 약 56.7fps
- 프로덕션 출력 전체: 846,029 bytes, 약 0.807MiB
- JavaScript: 약 642.55KB minified, 167.13KB gzip
- CSS: 약 6.75KB minified, 1.88KB gzip

현재 데스크톱 목표 중앙값 55fps와 하한 50fps, 초기 전송량 10MB 예산을 만족한다. Vite 기본 500KB JavaScript 경고는 Three.js 단일 청크 때문에 유지한다. 최종 30초 프로파일과 모바일 저품질 30fps 검증은 계획대로 M6에서 반복한다.

## 단순화와 남은 위험

- 충돌, 포즈, 세계 배치, 관문 안내, 감소 모션 카메라 피드백은 Three.js 장면과 분리된 순수 규칙으로 테스트했다.
- 반복 세계 오브젝트는 섬/상판/구름 세 개의 인스턴스 드로우로 묶었다.
- 통과 파동은 한 개의 재사용 mesh, 부스트 공기고리는 세 개의 고정 mesh를 재활용해 런타임 할당을 피했다.
- 장애물 충돌은 물리 엔진 대신 코스에 필요한 구 프록시 12개만 사용했다.
- 개발 QA 버튼은 제품 UI와 상태 모델에 새 프레임워크나 의존성을 추가하지 않고 프로덕션에서 제거된다.
- 현재 GLB는 1,600 triangle 블록아웃이라 가까운 화면에서 표면 세부가 제한된다. 실루엣과 리그 계약을 유지한 채 이후 에셋 패스에서 교체할 수 있다.
- 구 프록시는 복잡한 섬 실루엣보다 보수적일 수 있으므로 M6 플레이테스트에서 억울한 충돌 지점을 다시 튜닝해야 한다.
- 터치 완주 흐름, 접근성 자동화, Playwright 시나리오는 계획대로 M4 범위다.
