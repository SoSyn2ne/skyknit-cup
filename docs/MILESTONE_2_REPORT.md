# Milestone 2 검증 기록

> 상태: **완료 검증됨**
>
> 검증일: 2026-07-10

## 결과

- 12개 관문을 다음 관문 하나씩만 순서대로 통과하는 1랩 레이스를 구현했다.
- `준비 -> 3초 카운트다운 -> 레이스 -> 일시정지/완주 -> 재시도` 흐름을 기존 60Hz 비행 샌드박스에 연결했다.
- 타이머, 관문 카운터, 수동 `R` 리스폰, 1.5초 연속 코스 이탈 자동 리스폰, 1초 충돌 면역 상태를 구현했다.
- 리스폰은 경과 시간, 관문 진행, 부스트 잔량을 보존하고 다음 관문을 향한 안전 앵커로 비행 상태만 복구한다.
- 유효한 완주만 로컬 최고 기록으로 저장하며 손상된 값과 저장소 읽기/쓰기 실패를 무시한다.
- 준비, 카운트다운, 비행, 일시정지, 완주 HUD를 풀블리드 장면 위의 최소 오버레이로 추가했다.
- 실제 드래곤 리그, 세계 장식, 장애물, 터치 조작은 M3~M4 범위로 남겼다.

## 테스트 우선 증거

M2 규칙은 구현 전에 실패 테스트로 고정했다.

1. `courseProgress.test.ts`, `raceRuntime.test.ts`, `records.test.ts`, `course.test.ts`, `RaceHud.test.ts`는 대응 구현 모듈 부재로 각각 RED를 확인했다.
2. 레이스 시계/관문 통합 테스트 6개는 함수 부재로 실패한 뒤 최소 구현으로 통과시켰다.
3. 키보드 시작/일시정지/리스폰 및 lifecycle pause 테스트 3개가 실패한 뒤 1회성 명령 버퍼와 콜백을 구현했다.
4. 순수 규칙을 녹색으로 만든 뒤 렌더러와 HUD를 연결했다.
5. 마지막으로 실제 비행 모델이 부스트 없이 12개 관문을 120~240초 안에 통과하는 결정적 60Hz 완주 시뮬레이션을 추가했다.

최종 결과는 11개 테스트 파일, 102개 테스트다. 다음을 직접 검증한다.

- 고속 관통, 건너뛰기, 관문 안 머무름, 역방향 통과 거부
- 리스폰 직후 이전 관문 재집계 거부와 최종 관문 완주
- 카운트다운/레이싱 시계와 일시정지 중 시간·관문 동결
- 고도 `-12` 미만 또는 활성 구간에서 65 units 초과 상태의 1.5초 누적
- 1초 리스폰 면역, 부스트/이동 거리 보존
- 손상된 저장값과 저장소 예외 처리
- 12개 관문, 단위 법선, 코스 길이와 2~4분 완주 가능성

## 실제 브라우저 기능 검증

Codex 인앱 브라우저에서 실제 키 입력과 버튼 상호작용으로 확인했다.

- 비행키 입력 후 3초 카운트다운이 시작되고 `racing`으로 전환됐다.
- 자동 전진으로 첫 관문을 실제 선분 교차해 `0 / 12 -> 1 / 12`로 진행했다.
- 첫 안전 앵커 리스폰 뒤 두 번째 관문도 실제 비행으로 통과해 `2 / 12`가 됐다.
- `Esc` 일시정지 전후 1.1초 동안 위치와 `24,500ms` 타이머가 정확히 동결됐다.
- 일시정지 메뉴 리스폰과 `R` 리스폰 모두 관문 인덱스와 타이머를 보존하고 면역 시간을 시작했다.
- 개발 전용 `?qaCourse=1` 버튼으로 같은 순서 전이 함수를 12번 실행해 `finished`, `12 / 12`, 현재/최고/차이/재시도 UI를 확인했다.
- 재시도는 카운트다운, 경과 시간 0, 관문 0, 완료 시간 `null`로 초기화하면서 최고 기록을 보존했다.
- 강제 WebGL 실패는 캔버스 0개, 한국어 `alert`, 포커스된 다시 시도 버튼을 표시했고 재시도 후 정상 캔버스 1개와 저장 기록을 복구했다.
- 정상, 실패, 복구, 프로덕션 미리보기에서 브라우저 warning/error는 0개였다.

`qaCourse`, `QA 다음 관문`, `forceWebglFailure`, `__DRAGON_RACE_TEST__`는 프로덕션 JavaScript에 남지 않았다. 프로덕션 미리보기에서 두 개발 쿼리를 함께 전달해도 정상 준비 화면과 캔버스 1개만 표시됐다.

## 단순화와 남은 위험

- 관문 판정, 코스 이탈, 리스폰, 저장은 Three.js와 분리된 순수 함수로 유지했다.
- 다음 관문만 렌더해 미래 관문이 코스 신호를 방해하지 않게 했다.
- M2 HUD는 DOM과 CSS만 사용했고 UI/상태 라이브러리나 새 의존성을 추가하지 않았다.
- `qaCourse`는 브라우저 완주 검증만 위한 개발 분기이며 프로덕션에서 제거된다.
- 2~4분 기준은 결정적 자동 조향 시뮬레이션으로 통과했지만, 처음 보는 외부 플레이어의 체감 난이도와 실제 완주 시간은 M4/M6 플레이테스트에서 다시 확인해야 한다.
- 터치 전용 완주 흐름, 접근성 자동화, Playwright 시나리오는 계획대로 M4 범위다.
