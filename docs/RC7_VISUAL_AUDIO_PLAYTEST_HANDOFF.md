# RC7 비주얼·오디오 플레이테스트 인계

> 자동 상태: **RC7 / 비주얼·오디오 리마스터 자동 검증 완료**
>
> 사람 상태: **실기기·사람 플레이테스트 대기**

## 테스트 목표

새 드래곤과 세 지역이 실제 화면과 장시간 모바일 플레이에서도 선명하고 안정적인지, 탐험 BGM이 브라우저 수명주기에 맞게 자연스럽게 이어지는지 확인한다. 자동화가 대신할 수 없는 GPU 발열, 터치 피로, Safari AAC, 사람의 루프 청취와 음원 권리만 최종 판단한다.

이 문서는 위 자동 결과를 반복해 증명하기 위한 것이 아니라 실제 기기와 사람이 판단해야 하는 차이를 기록하기 위한 인계다.

## 실행 준비

- Windows/macOS/Linux 데스크톱과 Node.js `22.20.x`
- 저장소 브랜치 `codex/rc7-visual-audio-remaster`
- 모바일과 같은 Wi-Fi에 연결된 개발 PC

```powershell
node --version
npm ci
npm run build
npm run preview -- --host 0.0.0.0 --port 4173
```

데스크톱에서는 `http://127.0.0.1:4173/`, 실제 모바일에서는 터미널에 표시된 PC의 LAN 주소로 접속한다. 테스트 전에 브라우저 콘솔과 네트워크 기록을 보존할 수 있게 준비한다.

## 필수 기기 매트릭스

| 환경 | 방향·기준 화면 | 품질 | 입력 | 오디오 확인 |
| --- | --- | --- | --- | --- |
| 데스크톱 Chromium | 1440x900 이상 | high | 키보드 | Ogg, 헤드폰·스피커 |
| 실제 Android Chromium | 가로, 약 844x390 | low | 터치 | 선택 codec, 스피커 |
| 실제 Android Chromium | 세로, 390x844 또는 320x568 | low | 터치 | 선택 codec, 스피커 |
| 실제 iPhone Safari | 가로 | low | 터치 | AAC/M4A 폴백 |
| 실제 iPhone Safari | 세로 | low | 터치 | AAC/M4A 폴백 |

가능하면 고DPR iPhone과 4GB급 Android를 각각 포함한다. 각 기기에서 브라우저 버전, CSS viewport, DPR과 실제 선택된 오디오 codec을 기록한다.

## 필수 확인 순서

1. 저장값을 초기화한 뒤 준비 화면을 연다. 첫 사용자 동작 전 BGM이 재생되지 않고, 드래곤·명시적 `비행 시작` 버튼·음소거·볼륨이 겹치지 않는지 확인한다.
2. `하늘 탐험`을 시작한다. 첫 동작 뒤 BGM이 한 번만 시작되고 기본 볼륨 35%가 지나치게 크거나 작지 않은지 듣는다.
3. 음소거를 켰다 끄고 볼륨을 0%, 35%, 100%로 바꾼다. SFX 마스터 음소거와 BGM 전용 볼륨의 역할이 혼동되지 않는지 확인한다.
4. 볼륨과 음소거를 바꾼 뒤 새로고침한다. 저장된 설정이 복원되고 자동재생 정책을 어기지 않는지 확인한다.
5. 탐험 중 탭을 숨기거나 다른 앱으로 전환한다. BGM과 게임이 멈추고 복귀 뒤 같은 재생 위치에서 이어지는지 확인한다.
6. 지도에서 축제 중심섬, 바람 협곡, 구름 유적지를 차례로 목적지로 지정하고 모두 방문한다. 세 지역 랜드마크, 착륙장, 현재 동전과 HUD가 서로 가리지 않는지 확인한다.
7. 각 지역에서 먼 거리 low → 220 units 안 high → 260 units 밖 low 전환을 왕복한다. 구조물이 사라지거나 두 LOD가 겹치지 않고, 전환이 비행을 방해할 정도로 튀지 않는지 본다.
8. 세 지역에서 각각 착륙하고 즉시 재이륙한다. 지도, 목적지, 발견 상태와 현재 동전 기록이 예상대로 유지되는지 확인한다.
9. 각 지역 하늘동전 코스를 적어도 한 번 시작하고 한 지역은 10개를 완주한다. 구조물 근접 구간에서 동전·드래곤·다음 동선의 가독성과 카메라 클리핑을 기록한다.
10. 축제 중심섬 비콘에서 레이스에 들어간다. BGM이 즉시 멈추고, 레이스 일시정지·재개 중 시뮬레이션이 정확히 멈추며 BGM은 계속 중지되는지 확인한다.
11. 레이스를 완료하거나 탐험으로 돌아간다. 탐험 BGM이 처음부터 다시 시작하지 않고 이전 위치에서 이어지는지 확인한다.
12. OS에서 reduced motion을 켜고 다시 실행한다. 강한 속도선, 통과 파동과 반복 pulse가 줄어도 관문·바람실·현재 동전은 읽히는지 확인한다.
13. 헤드폰으로 루프 경계를 두 번 이상 연속해서 듣고, 같은 절차를 기기 스피커로 반복한다. 클릭, 무음 공백, 박자 점프와 SFX 대비 음량 문제를 타임코드와 함께 기록한다.
14. 실제 Android와 iPhone에서 각각 10~15분 동안 세 지역, 지도, 착륙, 동전, 레이스를 반복한다. 발열, throttling, 프레임 저하, 배터리 급감, 엄지 피로와 오입력을 기록한다.

## 통과 기준

- 준비 화면에서 사용자 동작 전 BGM 재생이 없고 5초 안에 비행을 시작할 수 있다.
- 세 지역의 대표 구조물, 드래곤, 활성 관문·바람실·현재 동전이 UI와 안개에 가려지지 않는다.
- LOD 왕복, 착륙·재이륙, 지도, 동전, 레이스 전환에서 빈 화면·중복 자산·상태 손실이 없다.
- 레이스·숨김 탭에서는 BGM이 멈추고 탐험 복귀에서는 기존 위치에서 한 번만 재개한다.
- mute, volume과 reload가 키보드·터치에서 일관되고 처리되지 않은 오디오 오류가 없다.
- Safari가 Ogg 실패를 사용자에게 노출하지 않고 AAC/M4A로 실제 재생한다.
- 헤드폰·스피커에서 각각 두 번 이상의 경계에 클릭, 공백 또는 명확한 박자 점프가 없다.
- reduced motion에서 과한 동작은 줄고 플레이 신호는 유지된다.
- 10~15분 모바일 플레이에서 조작을 방해하는 발열·throttling·터치 피로가 없다.

## 음원 권리 확인

자동 검증은 파일 무결성과 재생 동작만 증명한다. 프로젝트 소유자는 `Sovereign of the Sunrise Skies.m4a`의 제작자·권리자, 게임 및 저장소 배포 허용 범위, 수정본(Ogg/AAC loop) 생성 허용, 상업적 이용·크레딧·재배포 조건을 확인하고 근거 문서 링크를 판정표에 남겨야 한다.

모든 사람 판정 항목이 통과하기 전에는 상태를 **실기기·사람 플레이테스트 대기**로 유지한다.
